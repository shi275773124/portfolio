# 案例 3：素材雷达站——量化研究纪律移植到广告素材决策

## TL;DR

为「广告素材该追投谁、该淘汰谁」这个高频决策，建了一套带**量化审计层**的素材雷达站：面板回放、因子 IC 审计、前瞻账本（preregistration）。核心贡献不是可视化，而是**用统计纪律防止把噪声当信号**——包括如实承认样本不足（UNDERPOWERED 不判定）。

## 背景与问题

直播电商的素材投放是高频决策：每天要决定哪些素材追投、哪些淘汰。常见做法是看 ROI 排序——但单日 ROI 噪声极大（全量池 ROI 尖峰到 712/1596，均值完全失真），且「分配器建议」从没有被回测验证过是否真有区分度。

## 我做了什么

### 1. 基础雷达站（可见层）

- 每日自动抓取广告素材数据（TOP10 + 全量翻页 500+ 条）→ 快照存档 → 雷达站网页 + 在线表格
- 核心榜按「超额 × 权重」排序（相对账户基准的偏离，不是绝对 ROI）
- CTR 早警：对照上一份 7 日快照，FATIGUE / COLD / BUDGET_UP 三态
- 跑量力诊断：eCPM proxy 三因子相对倍数取短板定位（CPM 贵 / 点击弱 / 转化弱）

### 2. 量化审计层（真正值钱的部分）

**面板回放**：用 git 历史回放每日快照 → 素材×日期面板（20 天 / 856 条），让「过去任意时点我知道什么」可复现——防止用未来数据评判过去决策（look-ahead bias）。

**IC 审计**（因子有效性检验）：
- 对「CTR 预测未来 ROI」做日截面 rank IC 检验
- 结论如实：「ctr→未来 ROI 负方向未复现」（3 观测全负但由单日截面扛，最新 5 日全正）→ **判定 UNDERPOWERED，CTR 权重不动**——统计上不显著就承认不显著，不为了「有结论」硬编故事
- 一次复检发现量化层停摆 5 天（「计划接入」从未落地）→ 补齐并接进每日巡检，**停摆=事故**

**前瞻账本**（preregistration ledger）：
- 分配器每个建议落账本（当日 prereg）→ markout 期后回测
- 实证结果：建议组 ≈ 全覆盖合格池，split-test 4/10 胜 = **暂无区分度证据**
- 补充中位数/成本加权口径后（尖峰 ROI 炸穿均值），split-test 11/15 胜、评分 IC 12/15 正 → 上修为「弱正向区分度」——**同一数据，稳健统计量改变结论**

### 3. 分配器的两次证伪迭代

- v1 潜力榜：候选池=TOP10 → 复核证实「新素材消耗小天然进不了 TOP10」双重自锁（实测 47 条新素材过门槛 0 条，而结构缺口红灯挂着）→ 改全量池
- 冷启动哲学：只给新素材（≤14 天）分配探索预算——追投存量只会让老素材更集中，结构上不可能提升新素材占比

## 可迁移能力

- 量化研究纪律（IC / prereg / markout / UNDERPOWERED）移植到非金融场景的完整实践
- 「决策系统必须自己被审计」——分配器上线不等于结束，账本回测才是开始
- 稳健统计的实战敏感度（均值 vs 中位数在尖峰分布下结论反转）
