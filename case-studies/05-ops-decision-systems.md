# 案例 5：运营决策系统（SR 排班 / 薪酬闸门 / 目标拆解）

## TL;DR

把直播电商里三个高摩擦、高利害的运营决策做成算法+闸门：**主播排班**（金融夏普比率的运营化移植，分子口径三连修正）、**月度薪酬**（265 项机器闸门，Must Fix 不清不许打款）、**目标拆日**（锚点硬约束+等比闭合算法）。共同哲学：确定性约束交给程序，判断留给流程文档。

## 1. 主播排班：SR 稳定超额榜

### 问题

谁上早班/晚班决定收入分配，靠「谁最近表现好」的印象流排班争议不断。需要一个公平且统计上站得住的排序。

### 方案

把金融夏普比率（Sharpe Ratio）移植到直播班次：

```
SR = mean(主播班次超额) ÷ σ(班次残差)
```

分子口径经历**三连修正**（这段最能讲）：

1. v1 用 ROI → 发现受时段投放强度干扰，不是主播能力
2. v2 改单小时成交 → 时段基础量级差异污染（黄金时段天然高）
3. **v3 终版：时段控制残差** = 单小时成交 − 剔除自身后的同时段基准（只比「同时段你比别人强多少」）

弱样本 σ 全店兜底 + 样本门槛（≥1 月/≥30 班次），产出权重改成交额。

### 排班哲学（数据推翻直觉的部分）

- 「双班日对齐隔天轮」（top2 各 21 班最大化）被实测证伪：对标行业头部账号，头部主播双班率仅 19%，50% 隔天轮 = 2.6 倍疲劳强度 → 改**头部垄断 + 疲劳基准**：前排锚定 SR1/SR2，双班率 ≤20%、双班日错开、间隔 ≥5 天
- 中控三人按 50/30/20 加权分配，带作息约束（禁晚班次日接早班）

## 2. 月度薪酬表：265 项闸门

薪酬是打钱的事，错一个月才发现就是事故。做成三道闸：

1. **槽边界连续切分**：班次窗=下一班开播时间；满窗=实播覆盖窗口终点；早退保实值；无数据日按排班时长分摊
2. **名册闸门+异名表**：主播异名自动归一；费率以权威表为准
3. **265 项机器重算**（取数走原始值非显示值）exit 0 → 独立 agent 对抗审 → Must Fix 清空 + 用户确认费率 → 才可打款

实战：8 月表一天六轮治理（两轮对抗复核、全月槽边界重切、顶班拆行判例），265 项 Must Fix=0。开发中还连带揪出前一轮复核的**空验证**（探针没剥千分位 → 0 对 0 假 PASS），取数规则更正为原始值。

## 3. 目标拆日：锚点+闭合算法

月目标（数百万级）拆到每天，直接按天数均摊会让大场日目标失真。算法：

- 大场日是**硬约束锚点**（不参与缩放）
- 其余日按节奏权重（off 0.24 / bigplus 1.70 / new 1.45-1.60 / run 1.12-1.36 / 周末 1.12-1.22）× 等比缩放闭合：X=(月目标−锚点)÷Σ权重，余数塞月末
- 写前自检五刀（闭合/锚点/量级/结构/环比），写后必表尾口径注记
- 下钻两层：分场次目标（直播间 80% 口径）→ 复盘表铺全月目标

## 共同设计原则（三条系统通用的）

1. **算法给排序，人保留判断**：SR 榜是排序依据，特殊情形人工覆盖有据可查
2. **利害越大的产物，闸门越硬**：报告=机器刀复核；薪酬=265 项重算+独立对抗审+用户终审三级
3. **每个算法都有「被推翻史」**：v1→v2→v3 的修正是常态——每次修正都来自实据，不是拍脑袋

## 可迁移能力

- 把量化方法论移植到运营场景的翻译能力（SR、残差、基准污染都是金融概念）
- 高利害流程的「闸门思维」：机器可判定的绝不留给人工细心
- 算法公平性叙事：排班从「凭印象」到「有据可查」，薪酬从「月底扯皮」到「闸门清零才打款」
